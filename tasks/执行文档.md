## 1. 项目目标与功能范围（系统做什么）

系统是面向视障人群的可穿戴辅助导航与识别原型，包含核心能力：

- **盲道导航**：盲道检测/跟随、转弯提醒、避障、掩码稳定（LK 光流）
- **过马路辅助**：斑马线检测 + 红绿灯状态识别 + 对齐引导
- **物品查找/抓取引导**：语音命令找物品 → YOLOE 检测 + 追踪 → 手部引导 → 拿取确认
- **实时语音交互**：ASR 语音识别 + 多模态对话（文本/图像）+ 语音输出
- **Web 端可视化**：实时视频画面 + IMU 3D 姿态面板 + 状态信息

## 2. 整体架构（你改代码要知道“谁调用谁”）

### 2.1 分层结构

**A. 接入层（FastAPI 服务）**

- 负责 WebSocket/HTTP 路由、连接管理、推流与广播调度
- FastAPI/Starlette WebSocket 支持收发 **Text / Binary / JSON**，可用 `receive_bytes()` / `send_bytes()` 完成视频/音频二进制流联调 ([FastAPI](https://fastapi.tiangolo.com/advanced/websockets/?utm_source=chatgpt.com))

**B. 导航统领层（状态机 Orchestrator）**

- `NavigationMaster`：管理模式切换和全局“语音节流/冷却”

**C. 工作流层（每个业务一个 workflow）**

- `workflow_blindpath.py`：盲道
- `workflow_crossstreet.py`：过马路
- `yolomedia.py`：找物品

**D. 推理层（模型与 CV 算法）**

- YOLO 分割（盲道/斑马线）
- YOLOE 开放词表检测（物体）
- MediaPipe Hand Landmarker（手部关键点）([Google AI for Developers](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python?utm_source=chatgpt.com))
- 红绿灯检测（HSV + YOLO/分类）
- 光流稳定（Lucas–Kanade）

**E. 外部服务层（DashScope / 通义千问）**

- Paraformer 实时 ASR（流式识别）([AlibabaCloud](https://www.alibabacloud.com/help/en/model-studio/real-time-speech-recognition?utm_source=chatgpt.com))
- Qwen-Omni（多模态输入，输出可含语音）([AlibabaCloud](https://www.alibabacloud.com/help/en/model-studio/qwen-omni?utm_source=chatgpt.com))
- Qwen API OpenAI-compatible 方式调用（你代码里就是这样写的）([AlibabaCloud](https://www.alibabacloud.com/help/en/model-studio/qwen-api-reference?utm_source=chatgpt.com))

## 5. 数据流（联调必须照这个查）

### 5.1 视频（ESP32-CAM → 服务端 → 浏览器）

**上行（ESP32 → Server）**

- WS：`/ws/camera`
- Payload：Binary JPEG bytes

**下行（Server → Browser）**

- WS：`/ws/viewer`
- Payload：Binary JPEG bytes

> FastAPI/Starlette WebSocket 原生支持 `receive_bytes()` 与发送二进制帧，用于 JPEG/PCM 推流是标准做法。([FastAPI](https://fastapi.tiangolo.com/advanced/websockets/?utm_source=chatgpt.com))

------

### 5.2 音频（ESP32 麦克风 → ASR → 指令/对话 → TTS → ESP32 扬声器）

**上行：/ws_audio**

- Binary PCM16 流
- 控制命令：`START / STOP / PROMPT:<text>`

**ASR：Paraformer（实时）**

- 目标：partial “说话就显示”、final “驱动下一步”
- 文档：Paraformer 支持实时麦克风识别场景 ([AlibabaCloud](https://www.alibabacloud.com/help/en/model-studio/real-time-speech-recognition?utm_source=chatgpt.com))

**下行播放：/stream.wav**

- HTTP 音频流输出（WAV）

------

### 5.3 IMU（ESP32 → UDP → Server → Browser 3D）

- UDP：`12345` 接收 JSON
- WS：`/ws` 推送给前端 Three.js 渲染

## 6. 状态机机制（执行项目最重要的“业务开关”）

### 6.1 全局主状态机：NavigationMaster

**默认**：启动后进入 `CHAT`
通过语音指令切换：

- “开始导航/盲道导航” → `BLINDPATH_NAV`
- “开始过马路/帮我过马路” → `CROSSING`（或过街工作流启动）
- “检测红绿灯/看红绿灯” → `TRAFFIC_LIGHT_DETECTION`
- “帮我找一下XXX” → `ITEM_SEARCH`
- “停止导航/结束导航”等 → 回到 `CHAT`

### 6.2 关键的“稳定性设计”

- 红绿灯等分类结果使用 **多数表决滤波**（避免抖动误判）
- 语音播报有 **冷却时间**（避免刷屏、避免 ASR+TTS 互相抢占）

1. `navigation_master.py` 新增状态常量 `YOUR_NEW_MODE`

### 8.3 接入一个新模型（例如“楼梯/井盖/坑洞检测”）

规范流程：

1. `model/` 放权重文件
2. 写 `xxx_backend.py` 做推理 wrapper（返回统一结构：boxes/masks/conf/classes）
3. 在对应 workflow 中调用
4. 输出统一走 UI/语音模块（不要直接 print）

### 8.4 WebSocket 联调（视频/音频）

FastAPI/Starlette 的 WebSocket 支持二进制帧收发：

- 接收：`await websocket.receive_bytes()`
- 发送：`await websocket.send_bytes(...)`
  这与项目“JPEG/PCM 二进制推流”模型完全一致。([FastAPI](https://fastapi.tiangolo.com/advanced/websockets/?utm_source=chatgpt.com))

## 9. 性能与稳定性（你跑起来后马上会遇到）

### 9.1 GPU 并发限流（防爆显存）

项目用了 `GPU_SLOTS` 控制并发推理数量 + AMP 混合精度策略
常用环境变量：

- `AIGLASS_GPU_SLOTS=1/2`
- `AIGLASS_AMP=bf16|fp16|off`
- `AIGLASS_DEVICE=cuda:0|cpu`

### 9.2 提升帧率的方法

1. **增大检测间隔**（盲道/障碍物隔帧跑）
2. 使用更轻量的模型（或 TensorRT）
3. 前端显示与推理线程解耦（你已经有 bridge_io 缓冲）

## 10. Debug 排查指南（出问题照这个查）

### 10.1 视频不显示

- 看 `/ws/camera` 是否连接
- 看 `/ws/viewer` 是否有订阅者
- 检查 JPEG bytes 是否正确（长度>0，能 decode）

### 10.2 ASR 不触发

- Key 是否正确
- 是否发了 `START`
- 是否进入 cooldown/被热词打断
- 网络是否可达 DashScope

### 10.3 模式切换没效果

- 看 `NavigationMaster.state` 是否变化
- 看 workflow 是否在主循环被调用
- 看是否被 “语音冷却”吞掉了输出
