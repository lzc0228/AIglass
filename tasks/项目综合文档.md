# IROS 项目综合文档（全覆盖版）

**项目代号：OpenDescribe / Edge-Native Semantic Navigation**
**面向：视障人群（Blindness & Low Vision, BLV）的可穿戴辅助导航系统**
**目标会议：IROS**

------

## 0. 一句话总结（给导师/评审看的）

我们提出一种 **边缘端原生（Edge-Native）** 的可穿戴导盲系统：在 **Jetson（Nano / Orin Nano）** 上实现 **YOLOE 实时感知 + 任务启发式引擎加载 + 双因子语义重排 + 输出流去冗余 + IMU 闭环时域稳定**，并用 **结构化、可执行、低认知负担的自然语言提示** 替代云端 MLLM 的不确定延迟与“冗余播报”。

------

## 1. 背景与问题定义（Problem Statement）

### 1.1 现状反思：感知-认知鸿沟

目前基于 YOLOE 的复现更多停留在 “检测到物体” 的 **Perception 层**，但无法进一步理解视障用户的 **真实意图与任务需求**，导致输出信息冗余、不可执行。

### 1.2 对标与痛点：WorldScribe 的云端延迟风险

我们明确对标 WorldScribe，但其依赖云端 MLLM，存在推理延迟（Inference Latency），对避障类任务是致命风险（响应非确定）。
WorldScribe 的核心能力是：**意图相关描述 + 动态/稳定场景自适应描述长度**（动态场景更简洁，稳定场景更详细）。([arXiv](https://arxiv.org/abs/2408.06627?utm_source=chatgpt.com))

### 1.3 我们的优势与策略转型

- **Edge-Native（边缘原生）**：利用 Jetson 本地算力实现 **确定性延迟（Deterministic Latency）**。
- **Interpretability-First（解释性优先）**：摒弃“黑箱大模型端到端生成”，采用 **任务预定义编码 + 动态语义重排** 来增强鲁棒性。

## 3. 系统总体设计（System Overview）

系统定位：**主动感知、无需问答、低认知负担的可穿戴导盲平台**。

### 3.1 硬件组成（可穿戴系统）

- Jetson 嵌入式平台（早期写 Nano，但我们方案里也明确 Orin Nano 方向）
- 夹式摄像头：前向环境感知（无线优先，最次有线）
- 骨传导耳机：音频反馈输出
- 6轴 IMU（陀螺仪）：视角补偿 + 时域平滑（闭环反馈）
- （需求项）亮度自适应指示灯：根据环境亮度调节提示灯
- 形态方案“两手准备”：夹式拇指相机、眼镜形态

### 3.2 软件架构：三阶段 Pipeline（我们的核心框架）

完整 pipeline（按我们资料的 Stage I/II/III）如下：

#### Stage I：Intent-Driven Configuration（意图驱动配置）

- User Intent Input → Task Router
- 任务模式：Target Search / Path Navigation / Scene Exploration

#### Stage II：Edge-side Inference & Semantic Reasoning（边缘端推理与语义推理）

- Task-Specific TRT Engine（按任务挂载 TensorRT Engine）
- Scene Inference（场景推断） + Heuristic Re-ranking（启发式重排）
- JSON Stream Optimizer：去冗余、去噪、输出结构化结果

#### Stage III：Proprioceptive Alignment（本体感觉闭环对齐）

- 6-Axis IMU → Viewpoint Compensation
- Temporal Smoothing + Spatial Consistency（时域一致、空间一致）

## 4. 核心方法（Methods）

我们的方法关键词：**Semantic Maximization（语义最大化）**，在资源受限设备上做“信息最有用”的输出。

### 4.1 第一层：Task-Specific Engine Loading（面向任务的引擎加载）

**机制**：根据用户意图动态挂载对应 TensorRT 优化引擎。
**优化目标**：不重训模型，从算法层面减少内存驻留、提升特定类别召回率（Recall）。

> 会议记录里也提到“每个场景打包成 .engine 以加速”，但同时注意个性化权重会让 engine 静态化（使用中难修改）。
> 以及我们自己标注了一个关键问题：**“场景的 engine 不合理”**——这是目前设计风险点。

### 4.2 第二层：Two-Factor Semantic Re-ranking（双因子语义重排）

我们给出了明确公式与权重结构：
$[
S = Conf \times W_{task} \times W_{scene}
]​$

- **Scene Inference**：提取物体空间分布特征（Spatial Distribution），自动识别当前场景
- **Contextual Semantic Salience（上下文语义显著性）**：给出与场景/任务匹配的权重模型

> 会议记录中我们也提出：每个场景一个 txt 存 objects 与 weights，通过场景识别来映射权重并输出 ranked 结果。

### 4.3 JSON Stream Optimization（输出流优化）

目标：彻底解决

- 检测框重复（Redundancy）
- 低置信度背景噪声（Low-confidence Noise）
  实现 refined output（精细化输出）。

> 会议记录里也明确点名了“密集物体冗余框、重复识别覆盖”等工程痛点。

### 4.4 Proprioceptive Closed-loop Feedback（陀螺仪闭环）

通过 IMU 做 Viewpoint Compensation + Temporal Smoothing，在转头/行走视觉抖动情况下保持语义描述的时间一致性。

## 5. 语义感知自然输出生成模块（当前最大难点模块）

我们已经一致认为：**最难的是“输出那一部分”**，即“算完权重 + 热力图后，如何生成自然、可执行的语音描述”。

### 5.1 Top-3 关键物体筛选：四维度融合（全覆盖）

我们定义的核心逻辑是：基于权重 (O_i) 与热力图 Heatmap 数据，融合以下维度筛选 Top-3：

1. **视觉显著性（Heatmap）**：强度越高越优先
2. **(O_i) 得分**：我们的综合权重指标
3. **用户自定义偏好**
4. **场景相关性**：与街道/路口等环境强相关者更优先
5. **置信度（Conf）**（材料中也列出）

> 会议记录还提到可能缺一维：“任务匹配度/安全优先级？”作为待补充维度。
> 同时我们讨论过：Heatmap 也可以更直观解释成“危险性”，颜色越深越危险（尤其动态物体）。

### 5.2 输出必须包含的内容要素（闭环导航指引）

最终语音输出必须完整包含：

- **钟点方向**
- **距离信息**
- **物体间空间关系**
- **精准避让提示**（形成闭环导航指引）

### 5.3 语言风格要求（禁止机械播报）

我们明确要求：必须口语自然，不能“XX方向XX米有XX”的刻板罗列。

### 5.4 动态适配（对标 WorldScribe 的关键点）

我们的模块也要求：

- **动态环境（路口通行）**：简洁实时提示
- **稳定环境（人行道）**：补充必要细节
  这点与 WorldScribe 的“动态/稳定场景描述长度自适应”高度一致。([arXiv](https://arxiv.org/abs/2408.06627?utm_source=chatgpt.com))

### 5.5 推荐的输出组织方式（把“规范”变成可实现的算法）

下面是一个 **可直接实现的生成策略**（不依赖云端大模型，符合我们 Interpretability-First 路线）：

**Step A：选 Top-3 物体（排序得分）**
建议统一一个总分：
$[
Score_i = Conf_i \cdot W_{task}(i)\cdot W_{scene}(i)\cdot f(Heat_i)\cdot g(UserPref_i)
]$
其中我们已明确核心是 $(Conf \times W_{task} \times W_{scene})$ ，Heat/UserPref 可以作为乘性或加性项实现即可。

**Step B：生成“可执行语义结构”（中间表示）**
为每个关键物体构造字段：

- object_name
- clock_dir（钟点方向）
- distance_m（距离）
- relative_relation（与其它物体左右前后/遮挡/靠近）
- avoidance_action（向左绕/停一下/直行保持）
- urgency_level（由 Heatmap/动态性决定）

**Step C：自然口语合成（模板拼接，但不死板）**
模板不是“罗列式”，而是“行动式提示”：

- 动态危险优先：“先避险 → 再补充环境”
- 稳定环境：“先整体 → 再关键点 → 再行动建议”

**示例（路口动态）**

> “你左前方大概两米有辆自行车正在靠近，先往右侧挪一步；正前方三米是斑马线入口，跟着路沿直走就行。”

**示例（稳定人行道）**

> “前方路比较通畅，右侧一米有栏杆可以靠边走；左前方两米有垃圾桶，保持直行稍微偏右就能绕开。”
